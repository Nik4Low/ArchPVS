## Что лежит в репозитории

```text
ArchPVS/
  README.md                          ← эта инструкция
  docs/Титульник.doc                 ← титульный лист отчёта
  docs/Lab1/2352_2_1.docx            ← отчёт по ЛР1
  docs/Lab1/Замеры.xlsx              ← замеры, ускорение, эффективность, графики
  Lab1APVS_Un/
    Lab1APVS_Un.slnx                 ← solution Visual Studio
    Lab1APVS_Un_seq/                 ← последовательная версия (один процесс)
    Lab1APVS_Un_par/                 ← параллельная версия (Microsoft MPI)
```

В решении **два отдельных проекта**. У каждого свой `main`, поэтому они собираются независимо:

| Проект | Файл | Что делает |
|---|---|---|
| `Lab1APVS_Un_seq` | `2352_2_1_seq.cpp` | Последовательное умножение матрицы `A[M×M]` на вектор `x[M]` |
| `Lab1APVS_Un_par` | `2352_2_1_par.cpp` | То же, но строки матрицы раздаются процессам через `MPI_Scatterv` |

Аргументы обеих программ одинаковые: `M` (размер матрицы) и `runs` (число прогонов, берётся лучшее время).

## Как клонировать и открыть в Visual Studio

1. Visual Studio → **Clone a repository**.
2. URL: `https://github.com/Nik4Low/ArchPVS.git`
3. После клонирования откройте **не корень репозитория**, а файл:

   `Lab1APVS_Un/Lab1APVS_Un.slnx`

4. Solution использует формат `.slnx` (Visual Studio 2022 17.13+ или Visual Studio 2026).  
   Если версия старше и `.slnx` не открывается — откройте `.vcxproj` нужного проекта напрямую.
5. Если VS предложит **retarget** toolset (`v145` — это VS 2026): согласитесь и выберите свой набор инструментов (`v143` для VS 2022).
6. Конфигурация сверху: **Release | x64**.  
   Debug тоже собирается, но для замеров времени нужен именно Release (`/O2`).

Чтобы выбрать, какая программа стартует по F5: в Solution Explorer правый клик по проекту → **Set as Startup Project**.

## Настройка окружения MPI

Последовательный проект (`Lab1APVS_Un_seq`) **не требует MPI**.  
Параллельный (`Lab1APVS_Un_par`) без Microsoft MPI **не скомпилируется** (`mpi.h` / `msmpi.lib`).

Нужны **две** установки: Runtime (запуск `mpiexec`) и SDK (заголовки и библиотеки для компилятора). Это два разных установщика с одной страницы.

### 1. Visual Studio с C++

1. Установите Visual Studio 2022 или 2026 Community (или выше).
2. В Visual Studio Installer → **Modify** → workload **Desktop development with C++**.
3. Должны быть отмечены MSVC, Windows 10/11 SDK и C++ CMake tools не обязательны.

Проверка: создаётся обычный консольный C++-проект и он собирается.

### 2. Скачать Microsoft MPI

Страница загрузки: [Microsoft MPI v10](https://www.microsoft.com/en-us/download/details.aspx?id=105289)

На странице два файла. Ставить **оба**, в таком порядке:

| Файл | Что это | Зачем |
|---|---|---|
| `msmpisetup.exe` | **Runtime** | `mpiexec.exe`, служба SMPD, запуск процессов |
| `msmpisdk.msi` | **SDK** | `mpi.h`, `msmpi.lib`, переменные `MSMPI_INC` и `MSMPI_LIB64` |

Типичные пути после установки:

```text
C:\Program Files\Microsoft MPI\Bin\mpiexec.exe
C:\Program Files (x86)\Microsoft SDKs\MPI\Include\mpi.h
C:\Program Files (x86)\Microsoft SDKs\MPI\Lib\x64\msmpi.lib
```

### 3. Перезапуск после установки

Закройте Visual Studio, Cursor и все уже открытые терминалы. Переменные `MSMPI_*` подхватываются только новыми процессами.

Если ставили SDK, пока VS была открыта, — перезапустите VS, иначе будет `Cannot open include file: 'mpi.h'`.

### 4. Проверка, что MPI виден системе

Откройте **новый** PowerShell или «Командную строку разработчика для VS»:

```bat
where mpiexec
mpiexec -help
echo %MSMPI_INC%
echo %MSMPI_LIB64%
```

Ожидаемый результат:

```text
C:\Program Files\Microsoft MPI\Bin\mpiexec.exe
MSMPI_INC=C:\Program Files (x86)\Microsoft SDKs\MPI\Include\
MSMPI_LIB64=C:\Program Files (x86)\Microsoft SDKs\MPI\Lib\x64
```

Если `MSMPI_INC` пустой — SDK не установлен или не перезапустили терминал.

Проверка на 2 процесса без нашего кода:

```bat
mpiexec -n 2 hostname
```

Должны появиться два имени компьютера. При первом запуске Windows может спросить разрешение брандмауэра — разрешите для частных сетей.

### 5. Как проект подключает MPI

В `Lab1APVS_Un_par.vcxproj` для **x64** уже прописано:

- include: `$(MSMPI_INC)` и `$(MSMPI_INC)\x64`
- lib: `$(MSMPI_LIB64)`
- линковка: `msmpi.lib`
- отладчик: `mpiexec.exe -n 4 "$(TargetPath)" 5000 5`

Вручную в проектных настройках это дублировать не нужно, если переменные окружения заданы установщиком SDK.

Win32-конфигурации в solution есть, но MPI настроен на **x64**. Собирайте x64.

## Запуск программ

Формат аргументов:

```text
программа [M] [runs]
```

| Аргумент | По умолчанию seq | По умолчанию MPI | Смысл |
|---|---|---|---|
| `M` | 1000 | 5000 | размер матрицы и вектора |
| `runs` | 5 | 5 | число прогонов; печатается лучшее время |

### Последовательная версия

Из Visual Studio: Startup Project = `Lab1APVS_Un_seq`, F5 / Ctrl+F5.

Из терминала:

```bat
cd Lab1APVS_Un\Lab1APVS_Un_seq\x64\Release
Lab1APVS_Un_seq.exe 1000 5
```

Аргументы отладки в VS: проект → Properties → Debugging → Command Arguments, например `5000 5`.

### Параллельная версия (обязательно через mpiexec)

Не запускайте `Lab1APVS_Un_par.exe` двойным щелчком как обычную программу: будет один процесс, смысл MPI пропадёт.

Из Visual Studio: Startup Project = `Lab1APVS_Un_par`, F5. В проекте уже стоит:

```text
Command:          mpiexec.exe
Command Arguments: -n 4 "$(TargetPath)" 5000 5
```

Число процессов меняется флагом `-n` (синоним `-np`).

Из терминала (после сборки Release x64):

```bat
cd Lab1APVS_Un\Lab1APVS_Un_par\x64\Release
mpiexec -n 1 Lab1APVS_Un_par.exe 1000 5
mpiexec -n 2 Lab1APVS_Un_par.exe 1000 5
mpiexec -n 4 Lab1APVS_Un_par.exe 1000 5
mpiexec -n 8 Lab1APVS_Un_par.exe 1000 5
```

Пример серии замеров, как в отчёте:

```bat
for %M in (10 100 500 1000 5000 10000) do (
  for %P in (1 2 4 8 16) do (
    echo ===== M=%M  processes=%P =====
    mpiexec -n %P Lab1APVS_Un_par.exe %M 5
  )
)
```

В PowerShell:

```powershell
foreach ($M in 10,100,500,1000,5000,10000) {
  foreach ($P in 1,2,4,8,16) {
    Write-Host "===== M=$M  processes=$P ====="
    mpiexec -n $P .\Lab1APVS_Un_par.exe $M 5
  }
}
```

`size = 1` у MPI-программы — это не «последовательная версия»: коллективные операции всё равно вызываются. Для базового времени T₁ используйте **seq**-exe.

Ускорение и эффективность:

```text
S = T_seq / T_mpi
E = S / P
```

где `P` — число процессов (`-n`).

Не ставьте `-n` сильно больше числа логических процессоров: начнётся переподписка, время обычно растёт. На машине с 4 ядрами / 8 потоками разумный диапазон — 2…8 процессов.

## Типичные ошибки

**`Cannot open include file: 'mpi.h'`**  
Не установлен SDK (`msmpisdk.msi`) или Visual Studio не перезапускали после установки. Проверьте `echo %MSMPI_INC%`.

**`cannot open file 'msmpi.lib'`**  
Нет SDK или собираете не x64. Проверьте `echo %MSMPI_LIB64%` и конфигурацию **x64**.

**`mpiexec` не является командой**  
Не установлен Runtime (`msmpisetup.exe`) или `C:\Program Files\Microsoft MPI\Bin` не в PATH. Откройте новый терминал. Полный путь:

```bat
"C:\Program Files\Microsoft MPI\Bin\mpiexec.exe" -n 2 hostname
```

**Линкер: already defined main**  
Значит, в одном проекте снова оказались и `seq`, и `par`. В этом репозитории они разнесены по двум `.vcxproj`. Не добавляйте оба `.cpp` в один проект.

**Программа MPI «молчит» или висит**  
Часто брандмауэр. Разрешите `mpiexec` / `smpd`. Проверьте `mpiexec -n 2 hostname`.

**Время на M = 10 и M = 100 скачет или ускорение < 1**  
Это ожидаемо: вычисления короче накладных расходов MPI (`Bcast`, `Scatterv`, `Gatherv`, `Barrier`) и разрешения `MPI_Wtime`. Для выводов используйте M ≥ 500.

**Retarget / toolset v145 not found**  
Проект создавался в VS 2026. В диалоге retarget выберите toolset вашей студии (`v143` для VS 2022).

**Release vs Debug**  
В Debug оптимизации выключены, сравнивать с чужими замерами бессмысленно. Для таблицы — только **Release | x64**.
